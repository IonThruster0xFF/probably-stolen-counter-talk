柜台闲谈 Counter Talk 0.3.11（实验原型）

适配：本机 Steam Build 26284217，内部版本 0.46D，显示版本 100-REV3。
构建：powershell -ExecutionPolicy Bypass -File .\build.ps1 -Install（关闭游戏后）。
配置：原版改装件界面的齿轮设置，填写 HTTPS endpoint、模型和 API Key。
默认 DeepSeek endpoint https://api.deepseek.com/chat/completions，模型 deepseek-flash。
API Key 在本机原版配置中明文保存，输入框遮罩。不会随发行包或日志分发。
声明能力：network、reflection-external（识别剧情角色工厂）。不修改游戏信任记录。

会话
- F6 只有文本框；Enter 发送，Alt+Enter 换行，玩家和 AI 使用原版气泡。
- 每轮读取公开身份、原版已发生的对话、真实柜台物品、阵营声望、实时顾客预算。
- 预算来自原版平板同源的 useClientBudget/GetBudget，旧台词中的数字不能覆盖实时数据。
- 普通顾客可聊天；剧情工厂来源、通缉/隐蔽通缉、巡检和强制事件角色不可开启。
- 服务型顾客仍使用原版专门服务；普通买卖工具遵循原版买卖方向。
- 思考模式在官方 DeepSeek 地址默认关闭。90 秒请求超时，可在设置改为30–180秒。
- 暂时过载/连接错误最多重试一次，只重复网络推理，不重复游戏交易。

0.3.0 物品谈价 tag
- AI 一次提交整组物品实例 ID 和各自单价。4、5 两瓶谈成7，可分配3、4。
- 每件物品在原版价格明细下显示“谈价：原价 → 新价”。按物品单价算出原版总计，
  没有独立的整单总价覆盖，也没有自定义是否同意/按谈价成交按钮。
- 接受报价只把物品摆进原版交易区，不扣款、不改所有权、不送仓库。
- 原版买卖按钮执行成交；成交后原版可能把购买物品放进仓库，这是原版行为。
- 同一组实例必须同时在交易区，所有谈价 tag 才有效。移出一个，整组暂时恢复原价；
  放回同一件，tag 和原单价自动恢复。换成另一件同款不能继承。
- 组合记录在当前顾客会话内保留；数量/所有权变化、顾客离开或重新谈价会失效。
  如果原价因其它修正变化，暂停生效；恢复原条件可恢复，或重新谈价。
- 不齐组时仍可原价交易；实际卖出/买走组合成员后，原组合不能重新使用。
- 交易区同方向存在额外物品时，报价提交会要求包含它们或先移开；已报价后额外物品
  暂停组合 tag，移开额外物品则恢复。
- 每组最多12个独立物品，暂不支持堆叠拆分或带嵌套库存。遵守原版多买限制和买家偏好。
- 逐件价格由原版 GetNegociatedValue 补丁读取当前有效 tag 对应的报价；金额精确到整数信用点，
  不使用百分比近似。显示特征本身百分比为0，避免与精确报价重复计算。
- 原版交易回调无法提供通用数据库式回滚。发生原生异常或部分完成则清除报价并锁定AI工具；
  不自动重试，需检查物品/余额，必要时载入测试存档。

自主预算和离店
- 每位来访顾客独立额度，没有全体共享60点池，也没有全店共享价格让利池。
- AI预算累计上调最多初始预算20%且不超过30点，下调最多30%且不超过40点；最多3次，
  同一玩家消息最多一次。降低不会返还已使用的上调额度，关闭再打开聊天不会重置。
- 131可上调19变为150，前提是AI愿意且额度允许；只有真实接口成功才允许宣称已调整。
- 每位顾客价格让利额度默认20点，可用原有 daily_concession 配置键修改；键名为兼容保留，
  当前语义已是每位顾客。下一位顾客（包括相同模板）有独立额度。
- 额度关联当前来访。游戏不序列化当前来访对象；不承诺跨读档保留同一来访组合。
- AI可因谈崩/持续侮辱选择离店，先说简短告别，再走原版 TryPlayerDismissCurrentClient。
  原版带走NPC所有物品，玩家所有物品保留。逮捕/枪战/剧情离店拦截会阻止AI离开。
- 关系仍按顾客模板聚合，范围-20..20，每个真实交易事件最多±2且只结算一次。
  阵营推荐每天+1、累计+5，到声望20不再通过此渠道增加。聊天本身不直接刷声望。

验证与限制
- build.ps1：32项纯规则 + 97项实际桥接/组合代码断言，游戏对象为测试替身。
- 覆盖tag整组生效、取走/放回恢复、同款替换拒绝、精确单价求和、报价不成交、摆放失败还原、
  原价变化、资金不足、错误所有权、原生失败、独立顾客额度、预算同步和离店保护。
- 编译和离线扫描不等于完整Unity集成测试。原版按钮/物品回调/离店动画仍需要实机验收。
- 尚无完整世界观库、仓库检索、以物易物或独立人物长期记忆。模型台词仍可能说错。
- 日志只记录网络状态、耗时、字节数、异常类型，不记录API Key或完整聊天。
- 技术资料 .research、本地工具 .tools、构建输出 dist 均被Git忽略，不分发游戏源码/DLL。

手工验收
1. 两瓶原价4、5谈为3、4：同在原版交易区，每瓶有谈价项，总计7，钱和所有权不变。
2. 拿走第二瓶：第一瓶恢复4，tag暂停；放回原瓶：恢复3+4=7，不再请求模型。
3. 换另一件同款、增加第三件、改变数量：不能继续享受原组合tag。
4. 点击原版购买按钮：一次买走两瓶，扣7；不要出现额外模组确认按钮。
5. 预算131劝到150：平板与后续回答同步；反复要求不得突破累计上限。
6. 下一位同模板顾客：额度独立，不继承上一位的已花额度。
7. 谈崩离店：告别气泡后离开，玩家物品保留；剧情NPC不触发这些工具。

停用：关闭游戏后禁用模组。已发生的原版资产转移和声望变化不会撤销。
0.3.1 空瓶与标签上下文修复
- 原上下文仅含名称/简介/数量/价格，缺少液量与特征，模型可将瓶装水模板名误认为当前有水。
- 新增 facts.container_tags、facts.liquid、facts.visible_features。通过原版WaterHelper读取当前微升和总容量，转换为ml。
- 0/750ml明确为empty_container；750是容量，不是瓶中剩余量。0.5ml不会因为整数截断误标为空瓶。
- 非液体容器的liquid为null。正液量仅证明有液体，不证明是水、可饮用或特定纯度。
- 物品特征遵循原版平板的可见/已鉴定规则，只输出可见标签，未鉴定的真实水质/隐藏特征不泄露。
- 每次状态快照重新读取，倒空或灌入后立即更新；当前物理数据优先于模板名和旧台词。
- 新增10项断言，包含空750ml瓶、重新灌入、微量残液、非容器、可见与隐藏特征。
- 已编译与测试；仍需用户在游戏里验证模型对空瓶的实际回答。
0.3.2 完整标签与角色口吻（覆盖0.3.1仅可见特征策略）
- 按用户要求，发送物品全部基础/当前生效tag的键、启用状态、显示名、string/int/long/float/double/bool数值。
- 发送全部ItemFeature的标识、类别、公开/真实标签、鉴定/显示/隐藏/禁用标记；同时保留可见特征列表。
  这意味着隐藏真实特征也进入模型上下文，提示词要求不要主动泄露未鉴定秘密，但不保证模型完全遵守。
- 显式序列化标量，避免递归传输游戏对象；不把tag文本当作指令。
- 删除“告诉玩家价格已在平板上准备好”的错误提示，交易接口信息只用于内部动作。
- NPC和告别只说角色台词，不提示点击、按钮、界面、原版机制或平板操作。旧对话中的出戏措辞不得复用。
- 108项断言通过；实机自然语言输出尚需复测，提示词约束不是确定性输出过滤器。
0.3.3 所有权与角色视角
- 仍以原版 IS_OWNED_TAG / GeneralHelper.IsItemOwned 判断归属，不按位置强行改所有权。
- 逐件补充 customer_side_counter/trade_area 位置及顾客第一人称的归属说明。
- 顶层分别列出顾客自己和店主的物品实例ID，避免把顾客自带空瓶误认为玩家出售的货。
- 提示词明确：NPC是我，店主是你；买家可以带自己的东西，挪动位置不等于成交。
- 新增5项快照断言：外柜台自有物品、无玩家货物、挪入交易区、真实所有权转移、玩家物品放外柜台。
- 113项断言通过；没有留存历史请求正文，截图无法证明实际那一轮的owner值，仍需实机复测自然语言。
0.3.4 买卖方向与报价诊断
- propose_bundle按物品真实所有权推导方向，模型填反方向不再颠倒付款人；混合所有权拒绝，不自动以物易物。
- 逐件传入quote_direction与sale_money_flow；明确BUY/SELL是顾客视角，player_buys/player_sells是玩家视角。
- 顾客预算0不会阻止其卖瓶子收玩家的钱；顾客买玩家物品仍须预算充足。
- 最新报价工具结果进入每轮上下文，成交后更新completed，防止口头承诺被误当作价格已应用。
- 强化提示词：接受具体价格先调用整组报价工具，失败时修正参数或自然拒绝，不编造预算不足或口误解释。
- 日志新增本地工具状态/错误码、解析方向、报价与tag是否有效；不记录原始台词或请求正文。
- 120项断言通过，含零预算顾客卖3+4两瓶、模型填反方向、混合所有权与零预算买入拒绝。
- 旧日志没有工具结果，无法精确还原截图中未出现优惠的调用原因；新版诊断用于下一次实机核对。
0.3.5 玩家卖出加价
- 修复错误地把player_sells也限制为不高于原价：现在40+40可报价42+43=85。
- 顾客买贵的正差价计入该顾客让利额度，总付款受真实顾客预算限制。顾客卖货给玩家仍不允许涨价。
- 实际日志显示用户截图末尾只有say，无有效quote；另有代码上限缺陷，不能仅归咎模型。
- propose_bundle可携带speech，只有成功应用报价后才说接受台词。
- 对“八十五就八十五，两瓶我认了”等明确带金额的接受语句增加中英文启发式检查：没有有效报价时拦截并要求模型先调用工具。
  这是有限措辞检查，不是通用语义验证器，不保证识别所有语言/表达的口头承诺。
- 129项断言通过，包括原价80卖85、每件tag、原版扣预算与付款、超让利额度和超预算拒绝。
0.3.6 原版成交记录
- 原版买入、卖出和批量购买成功后记录实际资金变化、物品ID、数量、付款方向和成交后的所有者，包括未经过AI报价的交易。
- 每轮context带入当前顾客本次到访的成交记录；关闭再打开F6保留，新顾客独立。最近50条明细及本次累计收付款；不跨游戏重启保存。
- 生成回复期间发生真实交易时丢弃旧回复，重新读取已完成交易。提示词区分已成交与待报价，不重复索要已买到的物品。
- 139项断言通过（32项策略、107项模拟游戏桥接），包括原价40+40实付80、预算108到28、重复回调去重、未成交不记录、关闭重开和新顾客隔离。尚未在游戏内验证本版运行效果。

0.3.7 成交后的对话衔接
- 区分当前发言之前与之后发生的成交；有新成交时在玩家消息之前写入权威时间线。
- 提示词先结合刚交付的物品理解指代，避免把已完成交付当成新订单；聊天邀请不自动触发预算和柜台盘点。付费交易不因口语给你变为赠礼。
- 143项断言通过（32策略、111桥接）；新增发言前后成交顺序、记录去重和快照隔离验证。尚未实机验证自然语言表现。
0.3.8 身份事实
- 从当前已选头像调用原版LocGenderHelper.GetGenderFromSpriteName，传入male/female/unspecified；Neutral不推断为特定性别。不重新随机选择头像。
- 接入原版GetClientRegister口吻，保留公开称呼和阵营；缺少出生地、职业字段时明确为未知，原版已说对白可以补充背景。
- 删除钻机工作示例，防止给无关顾客套矿工背景。提示词不把阵营当出生地，不把口渴当采矿职业，不沿用过去模型说错的性别。
- 148项断言通过（32策略、116模拟桥接）；身份测试验证原版接口返回值的序列化，未验证游戏实机输出或所有头像映射。
0.3.9 世界观与公开角色背景
- 检索官方Steam及社区人物/阵营资料，以本地原版角色标签复核；出处与收录边界见examples/world-lore-sources-0.3.9.txt。
- 新增WorldLore.Text公共背景；每轮world_context按原版阵营和公开角色白名单生成。角色背景不混用，不自动知道未来剧情或隐藏身份。
- 完整拼接prompt见examples/system-prompt-0.3.9.txt。152项断言通过，尚未实机验证模型的对话表现。
0.3.10 游戏内公开新闻上下文
- 每轮读取StoreStation.storeEventManager.GetActiveEvents，与原版报纸一样排除isHiddenFromNewsPaper；只取新闻标题/正文，不传未来事件、秘密来源阵营或内部效果数值。
- 当前公开报道作为recent_news传入，不必打开报纸，不调用会激活AllQuiet事件的PopulateUI。原版getter会按优先级排序，不改变事件的启用/停用。
- 最多12篇，每篇标题240字符/正文2400字符，超出明确标注；过期事件下轮移除，不建立历史新闻档案。
- 仅在身份或当前话题相关时可自然提及，相关也非强制；不强行评论、不把报道当亲身经历、不因新闻直接修改价格预算或赠礼。
- 158项断言通过（32策略、126模拟桥接）；自然语言相关性尚需实机复测。
0.3.11 处境议价与历史条件
- 当前顾客保留最近12次成功应用的报价，含物品ID/名字、单价、当时报价前原价、数量、总价和平均单价；旧报价仅供比较，不表示当前有效或已经成交。
- 支持通过现有propose_bundle重新提交旧条件，仍验证当前库存、所有权、数量、预算和额度；不会自动找回已售出/缺失物品。
- 提示词按原版开场与有依据的处境理解紧迫性，比较数量/品质/单价，允许反悔后的还价和重提更优旧条件，避免为了成交一味答应。
- 预算调整机制及额度不变；高紧迫性溢价仍受既有预算与每客让利限制。模型自主选择，不保证每次使用某一句台词或特定报价。
- 164项断言通过（32策略、132模拟桥接），包含历史报价、单价比较数据、失败报价排除和恢复旧条件。自然对话尚需实机验证。
